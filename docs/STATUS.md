## Status values

| Value | Meaning |
|---|---|
| `not started` | No code yet. |
| `skeleton` | The package or crate exists and builds, but the contracted behaviour is not implemented, or only partly. |

| `working` | Implements its contract sections, and its lint, typecheck and tests pass locally. Not necessarily deployed. |
| `blocked-on-credentials` | Everything up to an external boundary is done, and the rest needs an account, key, device or approval that does not exist yet. The "Missing" column says exactly what. |

## What works end to end locally

`make e2e-web` brings up the native Convex backend, pushes the functions, builds and starts the real sync worker and the fake IMAP/SMTP servers (`akatsuki-fake-mail`, self-signed TLS through `MAIL_CA_FILE`), then: email-code sign-in → `POST /v1/connect/imap` → initial sync into Convex → sanitized bodies → archive and undo → draft and send (re-sanitized HTML, no Bcc on the wire, Sent copy appended, send complete in Convex) → IDLE delivery of new mail → account removal and purge → sign-out. The web app then signs in, onboards an IMAP mailbox, reads a sanitized body in the sandboxed frame, archives with `e` (checked on the server) and undoes with `z`. Gmail and Graph have no equivalent run: they need live OAuth clients and test mailboxes.

## Open issues and follow-ups

Not blockers for local development; listed so nobody rediscovers them.

- Desktop and mobile parity: send later (desktop), snippets and AI write (both), dictation (both), label rename/delete (desktop, mobile), desktop label create.
- Web: keys pressed inside a message frame do not reach the app; route-level code splitting beyond the signed-in chunk.
- Worker: Convex query for threads inside the window so resync can delete vanished threads (D-233); `assignedAccounts` fields for backfill horizon and identities (D-232, D-247); Gmail draft id mapping on adopt (D-245); SVG image proxy.
- Rate limit on `search.threads` (5/s) is not enforced: a Convex query cannot write limiter state (D-057, D-354).
- Convex: act on `senderPrefs.blocked` server-side so the web stops creating block rules (D-286).
- Large Gmail and Graph attachments are held in memory per request (base64 inside JSON).
- Batch 429s fail the whole batch for Gmail and Graph; the step is retried.
- On the next Rust toolchain bump run `cargo report future-incompatibilities` (proc-macro-error2 through gpui, D-357).
